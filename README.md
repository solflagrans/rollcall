# Rollcall

Rollcall — адаптивный электронный журнал посещаемости учебной группы. Проект развивается как
модульный монолит отдельными вертикальными сценариями.

## Реализованный этап

Первый продуктовый этап охватывает только учебную группу и её учебные периоды:

- создание группы без обязательного периода;
- просмотр и изменение названия группы;
- выбор системы периодизации при создании первого периода;
- создание, просмотр, переключение и изменение периодов;
- автоматическое название и календарный статус периода;
- предупреждение о пересекающихся датах без запрета сохранения;
- выбор периода по умолчанию при открытии группы;
- адаптивный AppShell, светлая/тёмная темы, loading/error/empty/success-состояния.

Auth, роли, состав группы, дисциплины, занятия, посещаемость и журнал намеренно отсутствуют.

## Модель данных

### `groups`

- `id` — UUID;
- `name` — нормализованное название до 80 символов;
- `periodType` — nullable enum: `semester`, `trimester`, `quarter`, `year`;
- `createdAt`, `updatedAt`.

Группа может существовать без периода. `periodType` остаётся `null` до создания первого
периода.

### `academicPeriods`

- `id` — UUID;
- `groupId` — внешний ключ на `groups` с `ON DELETE RESTRICT`;
- `number` — целое число от 1 до 99;
- `startsOn`, `endsOn` — PostgreSQL `date`;
- `createdAt`, `updatedAt`.

База обеспечивает `UNIQUE(groupId, number)`, корректный диапазон номера и
`startsOn <= endsOn`. Добавлены индексы для `groupId`, `startsOn` и `endsOn`.

Название, статус, выбранность и «активность» периода в базе не хранятся.

## Правила учебных периодов

Тип периодов принадлежит группе. При создании первого периода установка `periodType` и
вставка периода выполняются атомарно одним SQL-выражением. После этого изменить тип через
интерфейс MVP нельзя, а последующие операции не принимают тип от клиента.

Название вычисляется функцией `formatPeriodName` в несклоняемом формате:

```text
1 Семестр
2 Триместр
3 Четверть
1 Год
```

Календарный статус вычисляется по date-only значениям:

- `upcoming`, если `startsOn > today`;
- `current`, если `startsOn <= today <= endsOn`;
- `completed`, если `endsOn < today`.

При открытии `/groups/[groupId]` выбирается:

1. текущий период с самой поздней датой начала;
2. иначе ближайший предстоящий;
3. иначе последний завершённый.

Последний выбранный период не запоминается. Выбор определяется только URL и не изменяет
календарный статус. Пересекающиеся даты разрешены после явного подтверждения.

## Маршруты

```text
/                                             # переход к группе или её созданию
/groups/new                                   # создание группы
/groups/[groupId]                             # группа / выбор периода по умолчанию
/groups/[groupId]/edit                        # изменение названия группы
/groups/[groupId]/periods/new                 # создание периода
/groups/[groupId]/periods/[periodId]          # выбранный период
/groups/[groupId]/periods/[periodId]/edit     # изменение периода
```

Интерфейс намеренно не поддерживает переключение между несколькими группами.

## Окружение и Neon

Скопируйте пример и добавьте реальную строку подключения Neon:

```bash
cp .env.example .env.local
```

```dotenv
DATABASE_URL=
```

`DATABASE_URL` валидируется Zod в момент фактического создания DB-клиента и не попадает в
клиентский bundle. Не подставляйте фиктивное значение. Neon Auth пока намеренно не
подключён.

## Установка и запуск

Требуются Node.js 20.9 или новее и pnpm.

```bash
pnpm install
pnpm db:migrate
pnpm dev
```

Локальное приложение доступно по `http://localhost:3000`.

## Миграции

Первая миграция находится в `drizzle/0000_dear_starjammers.sql` и создаёт enum
`period_type`, таблицы `groups` и `academic_periods`, внешний ключ, ограничения и индексы.

```bash
pnpm db:generate  # создать новую миграцию после изменения схемы
pnpm db:migrate   # применить неприменённые миграции
pnpm db:studio    # открыть Drizzle Studio
```

`db:migrate` и `db:studio` требуют настроенный `DATABASE_URL`; `db:generate` работает без
подключения к базе.

## Проверки

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:watch
pnpm build
```

Unit-тесты покрывают нормализацию названия, форматирование периода, статусы, пересечения,
правила периода по умолчанию и Zod-валидацию. Интеграционные тесты сервисного слоя покрывают
создание и изменение группы/периода, атомарный откат, уникальность, принадлежность,
неизменяемый тип и overlap-confirmation.

## Известные ограничения

- тип периодов нельзя изменить после создания первого периода;
- удаление и архивирование групп/периодов отсутствует;
- последний выбранный период не сохраняется;
- переключателя между несколькими группами нет;
- Auth, роли и состав группы появятся на последующих этапах;
- дисциплины, занятия, посещаемость и журнал ещё не реализованы.
