# Перекличка

Адаптивный электронный журнал посещаемости учебной группы. Староста и заместитель управляют составом группы и дисциплинами, создают занятия и меняют отметки; студент видит только собственную статистику и историю.

## Стек и архитектура

Next.js App Router, React 19, строгий TypeScript, Tailwind CSS, Drizzle ORM/Kit, официальный Neon Serverless Driver, Neon Auth, Zod, React Hook Form, TanStack Table, next-themes, Vitest, Testing Library и Playwright. Целевая платформа — Vercel + Neon Postgres.

Проект — модульный монолит. `src/app` содержит маршруты и Server Components, `src/features` — формы и доменную логику, `src/server/actions` — защищённые Server Actions, `src/server/services` — запросы, `src/server/permissions` — единый RBAC, `src/server/db` — схема и миграции. Клиентские компоненты не обращаются к БД.

## Быстрый локальный запуск

Без внешних секретов доступен изолированный demo-режим на PGlite — совместимом локальном PostgreSQL. Production-код использует Neon.

```bash
pnpm install
pnpm db:migrate
pnpm db:seed:demo
pnpm dev
```

Откройте `http://localhost:3000`.

Тестовые учётные записи (пароль у всех `demo12345`):

- `headman@rollcall.test` — староста;
- `deputy@rollcall.test` — заместитель;
- `student1@rollcall.test` — студент.

Demo-пароль существует только в локальном адаптере и не сохраняется в прикладной базе. Самостоятельная регистрация работает в версии с Neon Auth; локальный demo-режим использует готовые аккаунты. `.env.local` исключён из Git.

## Neon и Neon Auth

1. Создайте проект Neon и включите Neon Auth с входом по email/паролю и обязательным подтверждением email.
2. Скопируйте `.env.example` в `.env.local`.
3. Установите `DEMO_MODE=false`.
4. Заполните pooled `DATABASE_URL` и `NEON_AUTH_BASE_URL` из Neon Console.
5. Создайте `NEON_AUTH_COOKIE_SECRET` длиной не менее 32 символов: `openssl rand -base64 32`.
6. Примените миграцию. Нелокальная база остаётся пустой: demo-seed для Neon запрещён.
7. Откройте `/register`: староста создаст аккаунт, подтвердит email и настроит свою первую группу. Профиль, группа, текущий период и членство старосты создаются одной транзакцией.

Интеграция следует Neon Auth SDK v0.2+: `createNeonAuth()`, `auth.handler()`, серверные `auth.getSession()`, `auth.signUp.email()` и `auth.signIn.email()`. Neon Auth хранит пароль, подтверждение email и сессию; прикладная БД хранит профиль, группы и членства.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Pooled connection string Neon Postgres |
| `NEON_AUTH_BASE_URL` | URL endpoint Neon Auth |
| `NEON_AUTH_COOKIE_SECRET` | Секрет подписи session cache, минимум 32 символа |
| `DEMO_MODE` | `true` только для локального demo-адаптера |
| `PGLITE_DATA_DIR` | Каталог локальной demo-БД |
| `DEMO_AUTH_SECRET` | Локальная подпись demo-cookie; не использовать в production |
| `E2E_BASE_URL` | URL для Playwright |

Не добавляйте реальные секреты в Git.

## База данных и миграции

Схема поддерживает несколько групп и периодов: профили, группы, учебные периоды, членства с ролью на уровне группы, дисциплины, занятия, отметки и audit log. Группа выбирает систему периодов — семестры, триместры, четверти или годы. Период хранит только номер и даты; подпись вроде `1 семестр` вычисляется приложением и не редактируется вручную. Миграции создают enum-типы, внешние ключи, `UNIQUE (lesson_id, student_membership_id)`, проверки дат и номера периода, а также необходимые индексы.

Создание занятия, массовое создание отметок и audit log выполняются в одной транзакции. Редактирование отметок также журналируется. Студент и дисциплина архивируются при наличии истории; физическое удаление разрешено доменными правилами только без связанных данных. Последнего активного старосту/заместителя нельзя деактивировать.

```bash
pnpm db:generate   # сгенерировать новую миграцию после изменения схемы
pnpm db:migrate    # применить миграцию
pnpm db:seed:demo  # пересоздать локальные demo-данные в PGlite
```

Локальный demo-seed создаёт одну группу, активный период, старосту, заместителя, 10 студентов, 4 дисциплины, 8 занятий и разнообразные отметки. Он требует `DEMO_MODE=true` и аварийно завершается в production, на Vercel и при попытке использовать Neon. Нелокальная база после миграции не содержит тестовых записей.

## Роли и безопасность

Роли `headman` и `deputy` имеют одинаковые права. `student` имеет только `attendance.readOwn`. Каждая серверная операция проверяет сессию, активность членства, permission, группу пользователя и принадлежность сущностей. Входные данные повторно проверяются Zod на сервере. Ошибки не раскрывают детали БД. Секреты не попадают в client bundle.

Посещаемость считается на лету:

```text
(присутствовал + опоздал) / (все занятия − уважительные причины)
```

При нулевом знаменателе показывается `—`.

## Проверки

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm build
```

Unit-тесты покрывают статистику, подписи периодов, permissions, правила архивирования/удаления и отображение статусов. Интеграционные тесты на настоящем PostgreSQL-движке PGlite проверяют транзакции журнала и обновление старой схемы периодов. Playwright проверяет вход старосты, создание занятия и изменение статусов, кабинет студента, запрет административного URL и одинаковый доступ заместителя.

## Деплой на Vercel

Подключите репозиторий и Neon integration в Vercel, добавьте production-переменные, выполните только миграцию против production branch, затем разверните стандартной командой `pnpm build`. Не включайте `DEMO_MODE` и не запускайте demo-seed в production. Рекомендуется применять миграции отдельным release job до переключения трафика.

## Ограничения текущей версии

- Самостоятельная регистрация создаёт новую группу для старосты. Полноценная отправка приглашений студентам и заместителям пока не автоматизирована.
- Один пользователь выбирает первое активное членство; UI выбора группы появится при фактическом использовании нескольких групп.
- Импорт/экспорт, обращения, уведомления, преподаватели, realtime и внешний API намеренно не входят в текущую версию.
- В журнале выводятся последние 50 занятий; это защищает страницу от неограниченной загрузки. Полная cursor-пагинация — следующий шаг.
